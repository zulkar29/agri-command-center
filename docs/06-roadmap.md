# ৬. রোডম্যাপ

সময়ের আন্দাজ দেওয়া হয়নি, কারণ এটা অন্য কাজের পাশাপাশি চলা একজনের প্রকল্প। ধাপের ক্রম ঠিক, তারিখ নিজে বসান।

## ধাপ ০: ইন্টারফেস (শেষ)

- [x] ১০ পেজের ড্যাশবোর্ড (রিপোর্টসহ)
- [x] নমুনা ডেটা ও সিমুলেটর
- [x] ECharts চার্ট
- [x] README
- [x] মোবাইল অ্যাপ (Expo), একই API ও নমুনা মোড

## ধাপ ১: হার্ডওয়্যার পরীক্ষা

- [ ] পাম্প কিনে বালতিতে প্রবাহ মাপা
- [ ] ESP32 ও একটা মাটির সেন্সর, ডেটা সিরিয়ালে দেখা
- [ ] সেন্সর ক্যালিব্রেশন (শুকনো ও ভেজা)
- [ ] রিলে দিয়ে পাম্প চালু-বন্ধ, সুরক্ষা ফিউজসহ

## ধাপ ২: ডেটা প্রবাহ

- [x] ডাটাবেস ও REST API (`backend/`: Go, Gin, PostgreSQL), ডকারে সব একসাথে
- [x] টেলিমেট্রি গ্রহণ — আপাতত সরাসরি `POST /api/v1/telemetry` ([05](05-device-protocol.md))
- [x] টেলিমেট্রির জন্য TimescaleDB — হাইপারটেবিল, ৭ দিন পর কম্প্রেশন, ঐচ্ছিক রিটেনশন, চার্টের জন্য বাকেট-গড় (`GET /api/v1/telemetry/buckets`)
- [x] ড্যাশবোর্ডে সিমুলেটরের জায়গায় আসল ডেটা (নমুনা মোড বন্ধ করলেই; ডেটা-সোর্স স্তর `src/services/farm.ts` এর `useLiveFarm`)
- [ ] MQTT ব্রোকার বসানো ও ব্রিজ (ডিভাইস যেন HTTP না হয়ে MQTT-তে কথা বলে)

## ধাপ ৩: নিয়ন্ত্রণ

- [ ] ড্যাশবোর্ড থেকে পাম্প কমান্ড, নিশ্চিতকরণসহ (REST কমান্ড চালু, আসল রিলে ডিভাইসের নিশ্চিতকরণ বাকি)
- [x] সময়সূচি ও নিয়ম সার্ভারে চলা (`backend/internal/engine` — অটো সেচ, Duration শেষে বন্ধ, সময়সূচি, ট্যাংকের নিয়ম r2; MQTT এলে কমান্ড ব্রিজে যাবে)
- [ ] ডিভাইসে নিরাপত্তা নিয়ম পরীক্ষা (সংযোগ কেটে, ট্যাংক খালি করে)

## ধাপ ৪: ব্যবহারযোগ্যতা

- [x] লগইন ও ভূমিকা (মালিক, অপারেটর, দর্শক) — JWT + রিফ্রেশ, Google লগইন ঐচ্ছিক
- [x] ব্যবহারকারী আমন্ত্রণ ও ভূমিকা বদলানোর UI (মালিক; পাসওয়ার্ড রিসেটসহ)
- [x] নোটিফিকেশন — টেলিগ্রাম (ফার্মের চ্যাট + প্রতি ব্যবহারকারীর চ্যাট) ও SMS (HTTP গেটওয়ে) হয়েছে; হোয়াটসঅ্যাপ ও অ্যাপ পুশ বাকি
- [x] আবহাওয়া সেবা (Open-Meteo, চাবি ছাড়া; r1 বৃষ্টি-নিয়মসহ)
- [ ] PWA হিসেবে ফোনে ইনস্টল
- [x] CSV এক্সপোর্ট (খাতা, মজুত, সেচের লগ — ড্যাশবোর্ডে)
- [x] PDF রিপোর্ট (লাভ-ক্ষতি, করণীয়, যা শিখলাম, পূর্ণ রিপোর্ট — ড্যাশবোর্ডের "রিপোর্ট" পেজ)

## ধাপ ৫: প্রকাশ

- [ ] ডকুমেন্টেশন: হার্ডওয়্যার তৈরি, ওয়্যারিং ডায়াগ্রাম, বসানোর গাইড
- [x] অনুবাদের কাঠামো (ইংরেজি আগে) — i18next, ড্যাশবোর্ড ও মোবাইল
- [x] ডকার, একটা কমান্ডে চালানো (`docker compose up -d --build`); প্রকাশিত ইমেজ (Docker Hub/GHCR) বাকি

## ধাপ ৬: বাড়ানো

- [x] ফসল তোলা ও ফলন রেকর্ড, পাম্পের সময় × প্রবাহ = পানির হিসাব, প্রতি কেজিতে লিটার (ব্যাকএন্ড, ড্যাশবোর্ড ও মোবাইল)
- [x] খাতায় মাঠ/ফসল ট্যাগ ও "মাঠ অনুযায়ী লাভ", মজুত ব্যবহারে কমা ও কেনার তালিকা
- [x] কাজে আসল তারিখ (`dueAt`) ও পুনরাবৃত্ত কাজ (`repeatDays`), সময় পার হলে সতর্কতা
- [x] SMS সতর্কতা, প্রতি ব্যবহারকারীর চ্যানেল, সাপ্তাহিক সারসংক্ষেপ (আসল SMS প্রদানকারীতে যাচাই বাকি)
- [x] মোবাইলে অফলাইন সারি (কাজ, খরচ, পরিদর্শন)
- [x] ভুল সেন্সর ধরা (আটকে থাকা, লাফ, অসম্ভব মান → সতর্কতা + ওই জোনে অটো সেচ বন্ধ)
- [ ] নিয়মের কাঠামো (`kind` + প্যারামিটার) — `kind` হয়েছে; প্যারামিটার ও ব্যবহারকারীর নিজের নিয়ম বাকি
- [x] ফসলভিত্তিক পানির চাহিদা ও ক্যালেন্ডারের টেমপ্লেট (`internal/crops/crops.json`, কমিউনিটি যোগ করবে; মান যাচাই বাকি)
- [ ] ছবি তুলে রোগ ও পোকার রেকর্ড (পরিদর্শন মাঠের সাথে জোড়া হয়েছে; ছবি বাকি)
- [x] পরের ফসলের সুপারিশ — পানি, রোগ-পোকা, পালাক্রম, মৌসুম ও বাজারদর মিলিয়ে কারণসহ নম্বর (`internal/recommend`; "নিজের আগের ফলাফল" সংকেত ১–২ মৌসুমের ডেটা জমার পর)
- [ ] একাধিক ফার্ম একটা অ্যাকাউন্টে
- [ ] তৈরি কিট বা PCB (ব্যবসার সম্ভাবনা, [07](07-business.md))
