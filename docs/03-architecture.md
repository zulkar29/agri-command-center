# ৩. সিস্টেমের কাঠামো

## বড় ছবি

```
[মাঠ]                      [ইন্টারনেট]                 [সার্ভার]               [ব্যবহারকারী]
ESP32 নোড  --HTTP-->   POST /api/v1/telemetry  -->  REST API (Go)  -->  PostgreSQL + TimescaleDB
সেন্সর, পাম্প <--কমান্ড--  (MQTT ব্রিজ আসছে)    (নিয়ম ইঞ্জিন চালু)  <--JWT--  ড্যাশবোর্ড (ব্রাউজার) / মোবাইল অ্যাপ
```

## অংশগুলো

| অংশ | কাজ | অবস্থা |
|---|---|---|
| ESP32 ফার্মওয়্যার | সেন্সর পড়া, ডেটা পাঠানো, পাম্প চালানো, নিরাপত্তা বন্ধ | বাকি |
| MQTT ব্রোকার | ডিভাইস ও সার্ভারের মাঝের ডাকঘর (যেমন Mosquitto) | বাকি (আপাতত ডিভাইস সরাসরি HTTP-তে পাঠায়) |
| ব্রিজ ও API | ডেটা ডাটাবেসে রাখা, কমান্ড পাঠানো, নিয়ম চালানো | REST API চালু (`backend/`, Gin); MQTT ব্রিজ বাকি |
| নিয়ম ইঞ্জিন | অটো সেচ, সময়সূচি, ট্যাংক-কম বন্ধ ইত্যাদি সার্ভারে নিয়মিত চালানো | চালু (`backend/internal/engine`, প্রতি ৩০ সেকেন্ডে — `ENGINE_INTERVAL`); নিয়ম r3/r4 বাকি ([06](06-roadmap.md)) |
| লগইন ও অনুমতি | JWT অ্যাক্সেস + রিফ্রেশ টোকেন, Google লগইন, তিন ভূমিকা | চালু ([08](08-developer-guide.md#লগইন)) |
| ডাটাবেস | সেন্সরের ইতিহাস, কাজ, আয়-খরচ, ব্যবহারকারী ও সেশন | চালু (PostgreSQL); সেন্সরের ইতিহাস TimescaleDB হাইপারটেবিলে — ৭ দিনের পুরোনো চাংক কম্প্রেস, ঐচ্ছিক রিটেনশন ([08](08-developer-guide.md#টেলিমেট্রি-ও-timescaledb)); নমুনা মোডে ড্যাশবোর্ড localStorage, মোবাইল AsyncStorage ব্যবহার করে |
| ড্যাশবোর্ড | দেখা ও নিয়ন্ত্রণ (ব্রাউজার) | চালু; নমুনা মোড বন্ধ করলে লগইন করে API-র আসল ডেটা ও কমান্ড |
| মোবাইল অ্যাপ | একই ফিচার, Android ও iOS (Expo) | চালু (`mobile/`); কানেক্ট স্ক্রিনে সার্ভারের ঠিকানা + লগইন |
| সতর্কতা ও নোটিফিকেশন | সার্ভারে সতর্কতা মূল্যায়ন; SMS, হোয়াটসঅ্যাপ, টেলিগ্রাম | চালু (`backend/internal/alerts`, পাঠায় `internal/notify`); টেলিগ্রাম (ফার্মের চ্যাট + প্রতি ব্যবহারকারীর চ্যাট) ও SMS চালু, হোয়াটসঅ্যাপ বাকি |
| আবহাওয়া | পূর্বাভাস ও বৃষ্টির নিয়ম | চালু (`backend/internal/weather`, Open-Meteo) |

## প্রযুক্তি বাছাইয়ের যুক্তি

- **React, Vite, TypeScript:** দ্রুত ডেভেলপমেন্ট, ডেভেলপারদের পরিচিত।
- **Tailwind ও shadcn ধাঁচের কম্পোনেন্ট:** নিজের মতো বদলানো সহজ, কোড নিজের হাতে থাকে।
- **ECharts:** ওপেন সোর্স, ভালো চার্ট, বাংলা অক্ষর চলে।
- **jotai:** ছোট ও মডুলার স্টেট ব্যবস্থাপনা (ফার্মের ডেটা থেকে auth পর্যন্ত সব অ্যাটমে)।
- **Go + Gin + PostgreSQL (backend):** একটাই ছোট বাইনারি, Raspberry Pi-তেও চলে; ডাটাবেস সবার চেনা।
- **TimescaleDB (টেলিমেট্রি):** আলাদা টাইম-সিরিজ ডাটাবেস (যেমন InfluxDB) নয়, PostgreSQL-এরই এক্সটেনশন — একই সংযোগ, একই SQL ও GORM, ব্যাকআপ একটাই; ARM64-এ চলে। পাওয়া যায় হাইপারটেবিল (সময় ধরে ভাগ), কম্প্রেশন আর রিটেনশন। এক্সটেনশন না থাকলেও API সাধারণ PostgreSQL-এ চলে, শুধু এই সুবিধাগুলো থাকে না।
- **TanStack Query:** সার্ভারের ডেটা নিয়মিত আনা ও হালনাগাদ রাখা সহজ।
- **Expo / React Native (মোবাইল):** একই TypeScript, ড্যাশবোর্ডের services ও state-এর যমজ কোড।
- **i18next:** বাংলা ও ইংরেজি, দুই ক্লায়েন্টে একই কী।
- **MQTT:** হালকা, ESP32-তে সহজ, দুর্বল নেটওয়ার্কে ভালো।

## সার্ভার কোথায় চলবে (সিদ্ধান্ত বাকি)

| বিকল্প | সুবিধা | অসুবিধা |
|---|---|---|
| ফার্মে একটা Raspberry Pi | ডেটা নিজের হাতে, ইন্টারনেট গেলেও স্থানীয়ভাবে চলে | বিদ্যুৎ ও রক্ষণাবেক্ষণ নিজের |
| ছোট VPS | দূর থেকে সহজে পাওয়া যায়, সবসময় চালু | মাসিক খরচ, ইন্টারনেট না থাকলে ফার্মের নিয়ম থামে |
| দুটো মিলিয়ে | ফার্মের নিয়ম ESP32-তেই, ডেটা VPS-এ | বেশি জটিল |

সুপারিশ: সেচের জরুরি নিয়ম (যেমন শুকনো চলা বন্ধ) ESP32-তেই রাখা, যাতে ইন্টারনেট গেলেও নিরাপদ থাকে। বাকি নিয়ম সার্ভারে।

## অফলাইন আচরণ

- ইন্টারনেট না থাকলে ESP32 শেষ জানা সময়সূচি ও নিরাপত্তা সীমা মেনে চলবে।
- ডেটা জমিয়ে রেখে সংযোগ ফিরলে পাঠাবে।
- ড্যাশবোর্ড "শেষ ডেটা কখন এসেছে" দেখাবে এবং পুরোনো ডেটাকে পুরোনো বলে চিহ্নিত করবে।
